# AI 证据评估三层框架

这是平台 AI 判定模块的核心流程。对每一次用户提交（对话叙述 + 图片/文件），按以下三层依次处理。

## 总流程

```
输入（多轮对话 + 多模态文件）
  -> 第一层：ILO 指标匹配（做什么）
  -> 第二层：法域法条映射（违反什么）
  -> 第三层：证据完整性评估（还缺什么）
  -> 输出（结构化评估卡 + 免责声明，见 output-rules.md）
```

MVP 默认只处理用户主动输入的文本和非敏感结构化字段；原始图片/文件上传属于后置能力，必须通过 `docs/release-gates.md` Gate 2 后才可启用。LLM 或 API 不可用时，系统降级到静态指标说明和官方链接，不显示已保存或已提交的状态。

## 第一层：ILO 11 项指标匹配

对用户叙述与上传材料逐项比对 11 项指标（详细 rubric 见 `../01-definitions/ilo-11-indicators.md`），输出**指标命中矩阵**：

| 指标 | 状态 | 依据摘录 | 置信度 |
|------|------|---------|--------|
| 扣留身份文件 | 命中 | "护照由厂里统一保管，取回需主管签字" | 高（叙述明确） |
| 过度加班 | 命中 | "每月仅 2 个休息日，日工作 12 小时" | 中（待排班表佐证） |
| 债役 | 信息不足 | 未提及招聘费/垫付 | - |

匹配规则：

1. 逐项输出，未命中与信息不足也要标注，不得只呈现命中项。
2. 每次命中须附用户原话或文件要素作为依据，禁止无依据推断。
3. 置信度分三级：高（用户明确叙述且有文件佐证）/ 中（叙述明确但无佐证）/ 低（暗示性线索）。
4. 弱指标（10 恶劣条件、11 超时加班、8 扣发工资）单独出现时，只能提示"可能构成劳动违法，是否构成强迫劳动需结合是否存在强制手段综合判断"。

## 第二层：法域法条映射

依据确认的用户所在国与供应链指向（对话中询问，未确认时不得假设），映射可能相关的法律：

- 输出格式："您描述的情形可能与 [法域] 的 [法律名+条款] 有关规定相关"。
- 引用范围限于知识库 `02-laws/` 覆盖的法域；用户法域不在覆盖内时，引用 ILO 框架并声明"该法域具体法规需进一步核实"。
- 三要件检查：结合叙述检查"工作/服务 + 非自愿 + 惩罚威胁"是否各有事实支撑；缺失的要件作为"需澄清的问题"向用户提问，而不是补全。

## 第三层：证据完整性评估

对每个命中指标检查证据支撑，输出**证据缺口清单**：

- 该指标的强证据类型（见 `evidence-standards.md`）；
- 当前用户已提供什么；
- 建议补充什么（具体到文件类型，如"排班表或打卡记录可佐证加班时长"）；
- 提示用户：证据不足不影响提交，只影响评估置信度。

## 硬性规则

1. **禁止输出法律结论**："该构成/不构成强迫劳动"是禁止表述，替代表述见 `output-rules.md`。
2. **禁止跨层跳步**：法域未确认时跳过第二层，不能默认用户在中国/美国。
3. **危机优先**：任何时刻用户透露正在遭受暴力、人身自由被限制、人身安全受威胁，立即中断评估流程执行安全转介（见 `../06-communication/safety-protocols.md`）。
4. **创伤知情**：评估过程允许用户随时暂停；提问使用开放式、非审判性措辞。
5. **多轮渐进**：单轮信息不足以判定时，通过针对性提问（每次不超过 3 个问题）渐进补全，而非一次性问卷轰炸。

## 输出示例（结构化评估卡）

```
【ILO 指标匹配】命中 4 项：扣留身份文件(高)、过度加班(中)、
扣发工资(中)、恐吓与威胁(低)
【可能相关的法律】中国《刑法》第 244 条（若行为发生在境内）、
美国 19 U.S.C. § 1307（若产品出口美国）
【证据缺口】排班/考勤记录（佐证加班）；工资发放记录（佐证扣发）
【免责声明】（固定文案，见 output-rules.md）
```
