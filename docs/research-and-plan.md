# 慢波 Manbo 强迫劳动举报辅助平台：证据、方案与风险评估

> 版本：v0.2（2026-08-31）
> 状态：研究与治理基线；方案 A 已确认，视觉原型已建立，生产应用尚未开发
> 结论等级：本报告不是法律意见、执法结论或市场预测

## 摘要

慢波 Manbo 的真实机会不是“替官方认定强迫劳动”，而是降低举报前的理解、整理和渠道匹配成本。现有仓库已经形成 ILO 指标、法域法律摘要、证据分级、危机沟通和转介规则的知识基础，但仍存在三类阻断问题：第一，部分法律更新和未来日期使用了二手来源或占位符；第二，原方案同时承诺匿名证据托管、公开公司页、地图、跨用户聚类和 B2B API，远超当前治理能力；第三，README 把研究描述为“已验证完成”，容易让使用者误把概念设计当成可用产品。

本次修订采用证据分级和发布门禁。ILO 定义与 11 项指标、欧盟《禁止强迫劳动产品条例》Regulation (EU) 2024/3015 的生效/适用日期、美国 CBP/UFLPA 官方入口属于可追溯事实；CSDDD 修订后的门槛、欧盟门户上线日期、动态实体清单数量、平台责任判例等若未能由一手来源在本仓库复核，统一标为待核实，不进入产品硬编码。产品路线采用方案 A：MVP 提供法域确认、结构化自述、指标映射、长期私密材料、AI 第一次初审、双模式语音、管理员审核、证据安全提示和官方链接；公开聚合和商业 API 分别在完成 DPIA、威胁建模、内容治理、申诉机制和法律审查后再评估。

**核心判断**：先建立可信的“举报准备层”，再考虑数据网络效应。平台的首要成功指标不是报告数量，而是安全完成率、来源可追溯率、误导率和高危情形正确转介率。

## 1. 研究范围与方法

### 1.1 研究问题

1. 哪些国际和法域事实足以支撑统一的初步评估框架？
2. 用户在举报前、举报中、举报后分别需要什么，而官方渠道无法提供什么？
3. 在人身安全、隐私、诽谤、AI 误导和跨境合规风险下，什么功能可以先做，什么功能必须后置？

### 1.2 范围与限制

研究对象是“强迫劳动举报辅助与信息整理工具”，不包含执法、法律代理、心理治疗、营救或事实核查服务。时间基准为 2026-08-31；动态网页、成员国转化法和未来生效日期必须在产品运行时再次核验。本报告只使用仓库文件与可访问的官方来源；没有可复核数据的市场规模、转化率、案件数量不作估算。

### 1.3 证据状态

| 状态 | 含义 | 产品使用规则 |
|------|------|-------------|
| 已核实 | 官方法律文本、官方机构页面或 ILO 一手出版物可追溯 | 可用于知识库事实，但仍显示法域与核实日期 |
| 设计建议 | 产品、技术或治理方案 | 必须写成“建议/拟议”，不得写成现有能力 |
| 待核实 | 来源为二手材料、页面动态、修法进行中或无法确认 | 不得硬编码；输出时附官方链接和时效提示 |
| 用户报告 | 用户提交的叙述或文件 | 永远标记“未经独立核实”，与官方记录分层 |

## 2. 法律与执法基线

### 2.1 ILO：统一的识别语言，不是平台的法律认定

ILO《强迫劳动公约》第 29 号公约第 2 条把强迫劳动描述为“以任何惩罚相威胁，强迫任何人从事的非自愿的一切工作或服务”。ILO 2012 年《强迫劳动指标》手册列出 11 项实务指标：滥用脆弱性、欺骗、行动自由限制、隔离、身体与性暴力、恐吓与威胁、扣留身份文件、扣发工资、债役、恶劣工作与生活环境、过度加班。平台可以把它们作为结构化提问和证据清单，但不能把命中数量转换为法律结论。单一指标，尤其是恶劣条件、欠薪或加班，不足以完成整体定性。

**设计含义**：AI 输出应是“用户原话/文件要素 → 指标状态（命中、未命中、信息不足）→ 证据缺口 → 可能相关法域”，并在每次评估末尾附固定免责声明。系统不得输出“你被强迫劳动”“公司违法”等结论。

### 2.2 中国批准状态的纠正

ILO 在 2022-08-12 的官方新闻稿确认，中国提交了第 29 号和第 105 号强迫劳动公约的批准文件；两项公约在提交后一年生效。因此，仓库中关于中国批准状态的错误说法已删除。国内案件仍需以中国现行法律、执法机关和专业法律意见为准，不能仅以批准状态推导个案责任。

### 2.3 欧盟：产品禁令日期可核实，实施细节需持续跟踪

EUR-Lex 对 Regulation (EU) 2024/3015 的元数据显示：文本日期为 2024-11-27，存在 2024-12-13 和 2027-12-14 两个生效相关日期；产品禁令的实际适用日期为 **2027-12-14**。条例针对在欧盟市场投放、提供或从欧盟出口的强迫劳动产品，属于产品监管路径，不等同于对某一雇主作出刑事认定。

仓库此前引用的“2026-06-26 门户上线”“匿名投诉细节”和若干实施指南来自非一手或无法在本审阅中稳定复核的页面，现改为待核实。产品不得把门户是否上线、成员国主管机构名称或匿名性当成静态事实；应在运行时链接欧盟委员会和成员国官方页面。

### 2.4 美国：贸易路径与行为路径分离

美国 19 U.S.C. § 1307 的关税路径关注全部或部分由强迫劳动生产的进口货物；CBP 的 Forced Labor/UFLPA 官方页面是举报和执法信息的首要来源。UFLPA 的新疆及实体清单推定、CBP 的扣留/排除/没收流程属于进口执法事实，不能被平台改写为“某用户举报已经证明企业违法”。18 U.S.C. § 1589/1590 等刑事条款属于行为路径，需由 DOJ、HSI、FBI 等有权机构处理。

实体清单和扣查统计会动态变化。本仓库只保留官方链接，不复制数量快照；任何“新增企业数量、累计批次、货值或 WRO 数量”在发布前必须重新抓取并记录日期。

### 2.5 其他法域：摘要只能做导航

德国 BAFA、英国 Modern Slavery Act、法国警惕法、澳大利亚和加拿大供应链披露制度、日本企业与人权指引及中国劳动/刑法，适用范围、门槛和举报人保护均依本国法及转化立法变化。知识库提供导航级摘要，不承诺完整或最新。用户法域不在已核实覆盖范围时，系统必须明确“需要进一步核实”，而不是套用邻近法域。

## 3. 用户任务与渠道缺口

### 3.1 JTBD：用户真正要完成的任务

用户通常不是要一份“认定书”，而是要在风险不明时完成四件事：安全地说清发生了什么；理解哪些事实值得记录；知道哪个官方/NGO 渠道与其行为地、居住地或产品流向相关；在决定举报或不举报后保留对自己有用的记录。平台应围绕这四个任务设计，而不是围绕“收集最多报告”设计。

### 3.2 官方渠道的结构性限制

官方渠道通常按法域和执法目的分割：CBP 处理进口产品线索，BAFA 处理特定企业供应链投诉，劳动监察/仲裁处理国内劳动关系，NGO 提供倡导或转介。匿名性、是否回执、是否反馈、是否需要实名和是否提供保护，都因渠道而异。平台可以做渠道比较和证据格式转换，但不能暗示自己是官方外部渠道，也不能承诺调查结果。

### 3.3 用户安全与数据最小化

跨境工人、签证绑定劳动者、未成年人和正在遭受暴力者面临的风险不同。任何上传、公开或跨用户关联，都可能暴露身份、地点、同事和家庭关系。默认策略应是：不要求真实身份；不要求为取证而冒险；原始证据默认不公开；短期会话优先于长期托管；危机信号优先于完整问卷。

## 4. 产品方案与发布边界

> **2026-08-31 方案 A 决策更新（优先于本章旧的 MVP 边界）**：首发架构采用模块化单体 + 独立媒体处理流水线 + 供应商中立 AI Gateway。用户主动删除前，案件、原始文件、录音、转写和修订稿长期保存，无默认到期时间；单文件上限 100 MB、单案件上限 2 GB。AI 做第一次初审，用户可持续补充并生成新版本；管理员可随时低频审核，系统自动记录访问和操作。首发同时支持语音输入/文字回复与实时语音/同步字幕。公开聚合、公司页、地图和自动外部提交仍后置。

### 4.1 定位

**慢波 Manbo = 举报准备与信息导航工具。** 它帮助用户把自述整理为可读的指标矩阵、证据缺口和官方渠道清单；它不调查、不认定、不营救、不替用户提交、不提供法律意见。

### 4.2 MVP（可先做）

1. 语言与法域确认：分别询问行为发生地、用户所在地、产品流向地，允许“不愿回答”。
2. 结构化自述：按 ILO 11 项指标渐进提问，单轮不超过 3 个问题，危机信号立即中断。
3. 证据安全清单：告诉用户哪些现有材料可能有帮助，以及不应为取证承担风险；不要求上传原件。
4. 评估卡片：输出命中/未命中/信息不足矩阵、证据缺口和可能相关渠道，固定附免责声明。
5. 官方链接目录：保存来源、法域、核实日期和动态链接；不承诺实时案件状态。
6. 本地或短期会话导出：用户可下载自己整理的文本；默认不建立公开账户或长期证据库。

### 4.3 暂缓功能与进入条件

| 功能 | 主要新增风险 | 进入条件 |
|------|-------------|---------|
| 加密证据托管 | 特殊类别数据、密钥丢失、传票和删除失败 | DPIA、威胁模型、密钥恢复/删除测试、保留期限、法律审查 |
| 公司页/地图/公开聚合 | 诽谤、SLAPP、反向识别、恶意刷量 | 内容审核、通知-行动、公司回应与申诉、人工升级、司法辖区意见 |
| 跨用户查重/事件聚类 | 匿名性削弱、错误合并、敏感推断 | 明确同意、可逆关联、误合并纠正、差分隐私/最小化评估 |
| 多模态 LLM 证据分析 | 幻觉、敏感文件外泄、供应商留存 | 零保留协议、脱敏、红队测试、人工抽检、故障降级 |
| B2B API/趋势产品 | 二次使用、来源许可、利益冲突 | 数据许可、聚合阈值、公益治理、审计和退出机制 |

### 4.4 推荐用户流程

```text
安全提示与危机筛查
  -> 法域/产品流向确认
  -> ILO 指标渐进自述
  -> 证据安全提示（可跳过）
  -> 评估卡片与不确定性说明
  -> 2-3 个渠道选项及其匿名/反馈差异
  -> 用户自行导出、保存或结束会话
```

## 5. 技术与治理方案

### 5.1 最小技术边界

MVP 可采用静态前端 + 无状态评估 API + 受控检索层。结构化输出使用 JSON Schema；法条和渠道只从带有 `last_verified`、来源 URL 和状态字段的知识库检索。默认不存储 IP、设备指纹、原始上传文件或完整对话；必须存储时，先完成 DPIA 和保留期限设计。LLM 供应商只接收完成必要脱敏的内容，并要求明确的训练/留存控制。

### 5.2 评估质量控制

建立“黄金案例集”覆盖 11 项指标、信息不足、危机、恶意举报、跨法域和多语言表达。每次模型或提示词变更都运行回归测试，至少记录：危机召回率、法律结论越界率、来源引用正确率、法域误判率、拒答率和用户可理解性。任何高危错误都触发版本回滚和人工复核。

### 5.3 治理角色

上线前必须指定：产品负责人（范围与门禁）、隐私负责人/DPO（适用时）、法律审阅人（目标法域）、安全负责人（威胁模型与密钥）、信任与安全负责人（滥用和申诉）、值班升级人（危机事件）。在没有这些责任人的情况下，不得开启证据托管或公开页面。

## 6. 路线图与衡量指标

| 阶段 | 交付边界 | 不包含 | 退出/进入条件 |
|------|---------|-------|---------------|
| 0：研究基线 | 来源登记、知识库状态、风险登记册、原型对话 | 真实用户数据、公开页面 | 法律事实抽查通过，所有高风险主张有状态 |
| MVP：举报准备 | 法域确认、指标评估、证据清单、官方链接、短期导出 | 原始证据托管、地图、公司页、跨用户聚类 | 黄金案例集通过；危机和越界错误达到门槛；隐私审查完成 |
| V1：受控托管评估 | 在有限法域试点加密证据托管 | 公开搜索、商业 API | DPIA、威胁建模、删除/传票演练、人工 SOP 通过 |
| V2：受控公开 | 经审核的聚合信息、回应和申诉 | 未经审核的实时排行榜 | 通知-行动、申诉、透明度报告、内容质量审计通过 |
| V3：数据合作 | 聚合趋势和受限 API | 出售可识别或可反推个人的数据 | 来源许可、公益治理、独立审计和退出机制通过 |

建议的首批指标是“安全完成率、危机转介正确率、法域确认完整率、引用可追溯率、法律结论越界率、用户主动删除成功率”，而不是报告总量或公司曝光量。当前没有真实使用数据，基线和目标值应在可用性试验后设定。

## 7. 风险结论

最高优先级风险不是模型答错一个术语，而是平台让一个处于危险中的人相信“匿名、加密或举报一定安全”。因此必须把安全承诺改为可验证的技术与流程约束，并明确在线行为仍可能留下痕迹。公开指控功能的法律风险与数据网络效应并不对称：少量错误内容即可造成不可逆伤害，而大量报告并不能自动提高事实准确性。路线图应先证明“用户能安全地获得有用信息”，再证明“平台能够承载公开数据”。详见 [`docs/risk-register.md`](risk-register.md) 和 [`docs/release-gates.md`](release-gates.md)。

## 8. 结论

慢波 Manbo 可以成为跨法域的举报准备工具，但当前证据不足以支持“全球公开举报数据库”或“已完成验证”的叙述。可持续的战略顺序是：先以 ILO 指标和官方来源建立可追溯的教育与整理层；用短期、最小化数据设计验证用户价值；再在法律、隐私、安全、内容治理和申诉机制成熟后逐步增加托管与公开能力。平台的中立不是一句免责声明，而是由不认定、不曝光、不承诺、可申诉和可删除共同实现的运行规则。
