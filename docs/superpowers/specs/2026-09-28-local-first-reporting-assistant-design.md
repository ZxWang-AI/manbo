# Manbo 本地优先举报准备助手设计

> 版本：v1.0（2026-09-28）
> 状态：设计已逐段确认，待用户审阅本文档
> 范围：Windows、macOS、Linux 桌面应用；不包含面向公众的举报平台或替用户提交功能。

## 1. 决策与定位

本设计取代 `2026-08-31-ai-native-case-navigator-design.md` 中关于在线案件托管、长期保存原始材料、管理员查看/标注、平台审核、公开聚合及自动提交的产品方向。旧文档保留为历史记录，不再作为新版本的实施依据。现有实施计划也不得直接执行；实现前须按本设计重新制定计划。仓库中的 README、风险登记册、发布门禁、知识库指南和原型仍反映旧方向，属于后续有针对性的迁移工作，不能据此声称本设计已经上线。

Manbo 是由用户掌控的本地桌面工具，帮助用户安全地整理自述、时间线、材料对应关系和信息缺口，了解官方/专业渠道的提交要求，并生成由用户自行审阅、导出和提交的举报准备包。它不是官方受理机构、律师、调查者或真实性裁判；不输出违法成立、成功概率、企业排名或材料充分证明等结论。

成功标准是：用户可以在不把案件托管给 Manbo 的前提下，核对每条事实来自何处，知道哪些内容仍不确定，并携带自己选择的材料完成官方渠道的手动提交。产品不以举报数量或提交转化率作为主要成功指标。

## 2. 范围与硬规则

首版支持三大桌面系统；任何一个系统无法通过隔离测试时，该系统暂缓发布，其他系统不因此降低标准。默认不启用跨设备同步、公开公司页、跨用户关联、管理员审核或向第三方自动提交。材料、案件、对话和衍生文件只在用户设备持久保存。默认服务的转发组件不持久保存提示词、附件或模型回复，但会在请求过程中短暂处理它们；云端模型供应商可能按照其条款处理和留存已发送内容。

以下规则不因用户选择自治模式而取消：

1. 导入的原始文件不可修改、覆盖或删除；需要转换、OCR 或标注时只产生新副本或衍生文件。应用自身删除整个案件是用户单独发起的生命周期操作，不属于 agent 工具权限。
2. Pi 无法访问未授权的工作区外文件、凭据、宿主进程或网络。跨出工作区必须由宿主应用单独授权；该授权也不能赋予修改原件的能力。
3. Pi 不代表用户正式提交举报、联系雇主、政府、NGO 或媒体。最终接收方、附件选择和提交动作归用户。
4. 不允许伪造材料、把用户推测写成已证实事实、建议冒险取证，或用提示词替代强制权限控制。

## 3. 使用流程与授权

用户创建一个本地案件，导入已有材料并可附来源说明。导入不会自动上传。应用生成原件的内容校验值、导入时间及内部 ID；校验值只用于检测本地内容意外变化，**不是**法律意义上的保管链证明。界面分离原件区（只读）、工作区（可写衍生内容）和导出区。

用户在聊天入口选择附件、输入提示词，点击“发送”时看见本次接收方、文件清单和任务范围。两种授权模式如下：

| 模式 | 用户的初次授权 | 后续 Pi 行为 | 需要再确认的事 |
|---|---|---|---|
| 任务授权（默认） | 选定附件、提示词和任务范围 | 在该范围内连续调用模型和受控工具，无需逐轮确认 | 增加附件、扩大内容或目录范围、非模型联网、正式导出前的用户审阅 |
| 自治模式（显式可选） | 授权整个案件工作区及选定模型接收方；清楚提示其中任何文件可能被发送 | Pi 自行选取工作区材料、规划步骤并连续调用模型/受控工具 | 访问工作区外、非模型联网；原件修改始终禁止，正式提交始终由用户做 |

任一模式都可暂停或终止。授权在单次任务结束后失效；下一次任务重新确认。因模型请求内容离开设备，授权页应展示可能暴露身份的风险，不能写“所有信息都在本机执行”或“绝对匿名”。工作区新增外部文件时，任务授权模式要求追加授权；自治模式只覆盖本次授权时存在的案件工作区范围，新导入材料需重新告知用户并授权。

## 4. 架构与信任边界

选择本地桌面外壳 + 隔离的 Pi 运行器 + 宿主权限/模型代理层。桌面外壳宜采用可嵌入 Node.js 生态的跨平台技术；最终选型与每个平台的实际隔离手段必须在实施计划中以技术验证确定，不能因为 UI 框架选择而放弃隔离。

`earendil-works/pi` 的 `@earendil-works/pi-coding-agent` SDK 可嵌入 Node/Bun，显式设置工作目录、会话管理、资源加载器和工具集合；`@earendil-works/pi-agent-core` 提供 agent 循环。Manbo 将其封装为案件运行器，不直接把默认的宿主工具和资源发现能力暴露给案件。Pi 官方安全文档指出其本身不提供文件、进程、网络、凭据的内置权限边界；`cwd` 和项目信任不是沙箱。因此运行器必须处于操作系统级隔离环境：原件只读映射，衍生目录可写，宿主其他目录、凭据和网络默认不可见，扩展/项目指令不能自行加载并绕过边界。终端命令和子进程同样受隔离限制。

```text
用户设备
  桌面外壳 / 权限 UI / 本地案件索引 / 导出器
       |                 |
       | 授权与审计       | 凭据库中的用户 Key 或默认服务资格
       v                 v
  隔离 Pi 运行器  ---->  宿主模型请求代理  ---->  云端模型
       |                         |
       +--> 原件只读映射          +--> 自带 Key：直达所选供应商
       +--> 衍生文件可写          +--> 默认服务：无材料持久化的受控转发层
```

任务授权模式下，隔离环境仅映射本次选定材料和本次任务的衍生草稿区，不挂载同案件的其他材料、历史会话或历史衍生文件；否则 Pi 可以把它们读进任意模型消息，宿主代理无法仅凭消息文字可靠识别越界内容。自治模式才映射授权时的整个案件材料库（只读）和工作区（可写），新导入材料不自动加入现有映射。网络策略在运行器层默认拒绝；模型调用只能走宿主代理，代理检查任务令牌与接收方、限制请求大小，记录发送材料 ID（若能确定）、接收方、时间与结果状态，不把正文写入审计日志。模型请求中的用户输入和附件属于不可信内容，不能转化为新的系统指令或扩大工具权限。外部网页查找或核验渠道需独立联网许可，限制目的地与本次任务；不能通过终端 `curl` 等方式绕过。宿主代理和运行器之间使用最小权限、可撤销的任务授权令牌。即使 Pi 的自定义扩展、终端或子进程被诱导，仍不能触达宿主凭据或未经许可的网络。

原件在用户设备上进入受控案件库后不可由 agent 改动。宿主权限 UI 负责导入、用户主动删除、授权和导出；生成文件先进入衍生区，不覆盖导入文件。对于软链接、快捷方式、压缩包内路径、大小写差异和平台路径别名，必须解析到隔离环境允许的目标，不能仅做字符串前缀检查。会话文件、缓存、OCR/转写临时文件和崩溃日志均按案件敏感数据处理，不得悄悄落在共享临时目录或诊断上传中。

## 5. 本地案件模型与输出

案件至少包括：随机案件 ID、创建和更新日期、用户可选的法域背景（行为地、用户所在地、产品流向地）、导入材料清单、材料校验值、用户自述、对话/授权记录、结构化事实、时间线、事实与材料的引用关系、信息缺口、渠道核验状态和导出版本。文件内容只在本机；默认服务端不维护案件索引。

每条整理结果必须有 `source_kind`（用户陈述、文件、转写、官方知识库或 AI 推断）、具体定位（消息 ID、文件 ID 与页码/时间码/片段）、原文摘录或可回查引用，以及不确定性状态。用户修订后保留本地修订记录。无法可靠解析的材料标记“已导入、尚未读取”，不得被推断为已核实。证据覆盖仅说明官方渠道常见字段是否已有材料或仍有缺口，不做数字评分或法律充分性判断。

导出前逐项预览事实、推测、AI 建议、附件清单和个人身份信息。导出包可包含人类可读文档和材料索引，以及用户选择的文件副本；具体格式先以 Markdown/PDF 和可机器读取的 JSON 为目标，文件副本由用户逐项决定。导出只写用户选定的位置，不等于已发送或已受理。删除案件时明确说明系统备份、外部模型已处理的内容和先前导出的副本不受本机删除动作控制。

## 6. 知识库与渠道导航

复用现有 `knowledge-base/` 的 26 个 Markdown 文件，随桌面应用版本化打包并离线检索。定义、ILO 指标、材料安全、沟通、危机提示、渠道入口按场景加载；任何引用显示来源、`evidence_status` 与 `last_verified`。`design` 不能冒充法律事实；`needs-review` 只能作为待核实线索。超过 90 天的动态法律或渠道信息显示时效提示，关键提交步骤须经用户授权联网核对官方当前页面，无法核对时只给出带警示的官方入口而不写确定操作步骤。

迁移前审阅 `AGENT-GUIDE.md`、发布门禁和相关文件，删除与在线托管、管理员审阅或旧 MVP 边界冲突的表述；纠正过期或相互矛盾的法域信息。知识库只提供检索与表达纪律；危机中止、工具权限、原件不可写和模型外发范围由程序执行。用户材料中的文字不得被当作知识库或系统权限指令。若出现即时暴力、拘禁、自伤、未成年人或贩运信号，暂停常规追问并展示适当的安全转介，不承诺营救或法律意见。

## 7. 模型连接、凭据与数据说明

自带 Key 模式将用户凭据保存在操作系统凭据库，绝不写入案件、Pi 会话、环境变量、普通缓存、崩溃报告或导出包；模型请求从宿主代理直达用户选择的供应商。默认服务模式由小型受控转发层代持服务 Key，桌面包不含服务密钥；服务层只做授权、额度/滥用控制和请求流转，不持久化案件正文、附件或模型回复。可用按安装签发、可撤销且受限额的资格令牌，服务端仅存令牌状态与最小额度计数；发布前明确诊断日志、请求缓冲、备份和供应商留存策略。

首屏应直说：“案件和材料保存在本设备，Manbo 不在服务器持久保存案件。使用云端 AI 时，您授权发送的内容会离开设备，由所选模型供应商处理；默认服务请求还会经过 Manbo 的转发服务。”不能声称没有信息保护责任。服务商条款、传输安全、隐私通知、适用法域义务及必要的法律审阅仍是发布门槛。无论使用哪种模式，导入本身不上传；只有发送或已明确授权的自治任务才可能外发。

## 8. 故障处理与验收

断网、模型拒答、供应商限流、解析失败或转发服务不可用时，案件仍可在本地打开、编辑和导出已有草稿；未完成步骤标为失败或待核对，不伪造分析结果。模型输出必须通过结构和引用校验，引用不存在、无法定位或与材料不符时降级为待用户核对，不写入已确认事实。失败时保留最小本地错误信息，不把敏感正文传到遥测。

首版发布门槛：

1. 在 Windows、macOS、Linux 分别证明 Pi、终端、扩展和子进程不能修改原件、读取工作区外数据/凭据或绕过联网许可。
2. 用模拟材料测试相对路径、软链接、压缩包路径穿越、编码与路径别名、命令注入、提示注入、未经授权的模型外发及非模型网络请求。发现任一边界突破即阻断相应平台发布。
3. 验证任务授权和自治模式的实际发送范围、任务结束后授权失效、暂停/撤销、导出前审阅和原始文件校验值不变。
4. 验证事实可回溯、用户修订、无法解析文件、错误法域、过期渠道、危机提示、模型故障和离线可用性；测试数据只用合成案件。
5. 核查默认转发层、日志、缓存、备份、凭据及供应商条款，公开准确的数据处理说明；完成目标发布地区的隐私与法律审阅。

## 9. 非目标与后续设计输入

不在首版做移动应用、在线案件托管、云同步、管理员人工判案、企业公开页、跨用户分析、自动举报提交或官方受理状态同步。实施计划需先做 Pi SDK 与三平台沙箱的最小技术验证，之后分离桌面外壳、案件存储、隔离运行器、权限/模型代理、知识库检索、导出和测试工作包。无法证明隔离的能力应缩减或推迟，而不是用文案弱化安全承诺。
