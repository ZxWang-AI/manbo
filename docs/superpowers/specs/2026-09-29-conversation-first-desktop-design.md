# 慢波：对话优先桌面工作台与自带 Key 模型连接

> 日期：2026-09-29
> 状态：界面、范围、数据边界与验收设计已逐段获用户确认；本文待用户审阅。
> 适用：`main` 分支的本地优先 Electron 应用；旧在线平台分支仅作备份。

## 目标与决策

慢波首先是能自然交谈的桌面助手：普通问题无需案件或附件；进入案件后仍可普通交谈，需要分析材料时由用户逐项选择并确认。对话服务于事实梳理、证据来源、缺口与举报准备，但不替用户判断违法成立或正式提交。采用用户选择的 **B·常驻证据栏**，而不是以表单为中心的小聊天框。模型由用户自行配置 API Key；应用不内置共享 Key、不提供默认服务转发，也不在慢波服务器保存案件。用户选定的供应商可能按自身政策处理或留存发送内容，不能承诺“所有信息都在本机执行”。

本轮交付真实的自带 Key 对话与受控附件发送；Pi 的文件、终端及独立联网工具仍未开放。三平台隔离门槛未通过时，不以“自治模式”名义放宽权限或暗示这些工具可用。

## 界面与交互

- 左侧：新建普通对话、普通对话历史、案件列表和案件对话入口。两类对话都只在用户设备持久保存，互不混用；案件入口显示材料数量。切换对话不会自动选附件。
- 中央：宽消息流、清晰的用户/助手区分、固定在底部的可多行输入框和附件 chips。输入框可直接提问；发送按钮仅依赖非空提示词及可用的模型配置，不依赖附件。对话可以是普通问题，不能每次强迫用户填写任务表单。消息明确区分真实供应商回答与“本地演示回复”；后者不声称具有通用知识或已分析材料。
- 右侧：当前案件的材料清单、逐项勾选、导入、当前模型、授权与任务状态；普通对话时显示简洁的“未连接案件”状态。窄窗口可收起或弹出该栏，不让中央聊天被挤到不可用。模型设置保留可见入口，不占据输入主路径。
- 数据边界用首次使用说明和简短常驻提示表达：导入不上传；发送前明确说明用户选中的供应商、上下文及实际外发内容；原件不可由 agent 修改。不得写“本页面不承担额外信息保护责任”。
- 未配置有效 API 时提示配置路径。本地 Demo 可用于试交互，必须持续标明“不联网、模拟回复”；不自动伪装为默认真实模型。发送失败保留输入草稿。

## 对话及授权模型

普通对话有独立的本地 conversation ID 和记录，不创建空案件。案件对话引用现有案件 ID；仅显示材料清单不代表模型已读材料。首次真实云端发送先在本机生成不可变预览，列出接收方、模式、提示词、选中材料、每份材料实际发送形态、大小或页码范围，以及会带上的历史消息范围。用户确认的快照与实际请求不一致时拒绝发送并重新预览。无附件普通提问也须首次告知所选供应商；随后同一供应商、同一干净上下文段内的纯文本追问可连续发送，输入区始终显示接收方和上下文状态，不必每轮弹窗。添加/更换附件、切换供应商、引用敏感历史或扩大任务范围时重新预览并确认。任务授权只覆盖确认时的材料与限定上下文；连续模型调用不得越界。

历史上下文不是全部自动重放。每条消息记录它所依赖的材料 ID/敏感来源；用过证据的用户消息、衍生的助手回答及其后的连续上下文都视为可能含证据。后续无附件提问只从新的“干净”上下文段构造请求，不包含此前敏感段；界面提醒模型不会记得先前材料。若要继续讨论旧证据，重新选中相关附件并在预览中授权相应历史段。历史正文不能只凭标签就视为无敏感内容；预览必须让用户查看实际将重发的消息，且不能悄悄引用案件中的其他对话、文件或知识库。普通对话只带本对话中已明确授权的上下文。

自治模式在本轮真实模型界面中标为“待文件/终端隔离验证”，不可启用假自治；现有 Demo 只可演示授权概念。将来通过三平台验证后，再单独实现全案件快照与工具权限，不从这份规格推断已获授权。暂停/撤销只针对实际运行中的任务；中止当前模型请求后不得继续自动调用，已到达供应商的数据无法撤回。

## 部件及数据流

1. **本地会话库**管理普通/案件对话、来源标记和干净上下文段；不把 Pi 默认会话文件或 API Key 放到全局缓存。现有 `conversations.mjs` 仅支持单案件对话，需添加普通对话与多对话索引，同时保持旧记录可读。
2. **附件准备器**仅通过案件 ID 和清单中的证据 ID 读取本机受控副本；发送前复核原件副本的大小/哈希。首轮支持有明确编码的文本、可在本地提取文字的 PDF，以及经所选接口验证支持的图片。文本/PDF 发送受长度限制的提取片段及页码/来源，不声称发送了原 PDF；扫描版无文字、加密文件、无法解码文件、超限及未支持格式在发送前阻止。图片发送格式和大小须与接口能力匹配，预览标明图像字节会外发。提取结果只作内存请求材料或受控本机衍生数据，绝不覆盖原件。
3. **出站预览/授权器**在读取内容并确定实际 payload 后生成快照，记录接收方、提示词、上下文消息 ID 与摘要、材料 ID/哈希/形态和请求大小；确认与发送使用同一快照。确认后会话的同范围纯文本后续请求重新组装并校验仅含该段已授权上下文和新输入，新增材料或扩大范围则撤销旧授权并重新确认。业务层按 ID 限定读取，不能只靠渲染器勾选状态。只有主进程能访问原件副本和凭据。
4. **模型连接器与 Pi 无工具会话**使用 `@earendil-works/pi-coding-agent` 的受控会话能力、显式模型配置和内存资源配置；没有默认工具、扩展、技能、项目指令及资源发现。所选用户 Key 从 Electron 主进程的系统加密存储读取，只用于本次所选供应商的 HTTPS 请求，不进入渲染器、Pi 持久会话、环境变量、案件正文或日志。连接器优先复用 Pi 支持的 OpenAI Chat Completions 兼容协议；开发时验证自定义模型/凭据注入能否保持上述边界。若 SDK 无法以受控方式满足，必须先解决边界，不直接启用宽权限 Pi 默认运行器或用一个暗中的第二套 agent 冒充 Pi。
5. **主进程 Broker**校验确认快照、供应商/模型、请求大小、附件与上下文范围，才允许唯一的模型出站通道。自定义 Endpoint 需 HTTPS，拒绝本机/内网目的地和跳转至不同目的地；禁用隐式重定向，避免 Key 被转发。接口能力（特别是图片）须显式验证，不因“兼容”字样推断支持。出站记录仅保留本地最小元数据（时间、接收方、授权材料 ID、结果），不保存秘密或请求正文作为诊断日志。

本轮不新增外部网页抓取、自动举报、任意文件读取、终端运行、跨案件检索或默认服务。现有本地知识库的离线资料可作为后续受控检索输入，但本轮不能暗中拼入普通聊天请求。原件不可修改规则保持独立于提示词和模型行为。

## 错误、隐私与验证

断网、认证失败、限流、超时、取消、解析失败、模型不支持或上下文超限时，不生成伪助手回复，不标记为已分析。草稿保留在本机；若请求可能已到供应商但响应丢失，显示“不确定是否已接收”，再次发送须用户主动确认，避免暗中重复外发。报错不展示 Key 或敏感正文。模型回答标为待核对，事实与推断分开；不自动写入已确认事实。

测试先于实现，全部使用合成案件：普通聊天无需案件/附件；案件内无附件不读取材料；预览与实际 payload 一致；文件篡改、无文字 PDF、图片不兼容及过大文件均被拒绝；敏感历史段不会无授权重发；更改接收方、材料或提示词使确认失效；凭据不进入渲染器、记录、日志或导出；失败/取消不会出现模拟成功；Demo 不联网。运行 Node 测试、差异检查以及 Electron 窗口交互检查。Windows、macOS、Linux 的真实供应商/附件路径与 Pi 隔离分别验证；未测的平台不能据此宣称通过发布门槛。

## 与旧设计的关系

本规格收窄 `2026-09-28-local-first-reporting-assistant-design.md` 中的“默认服务”设想：现在只允许用户自带 Key，旧文档的默认转发服务不在当前路线。既有自治描述仍是将来隔离验收后的目标，不是本轮可用能力。旧在线平台分支不迁移到当前实现。本规格通过后另写具体实施计划，按小步测试推进。
