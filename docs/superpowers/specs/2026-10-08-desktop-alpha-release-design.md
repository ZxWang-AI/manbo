# 慢波 Manbo：三平台 Alpha 安装包设计

> 日期：2026-10-08（Asia/Shanghai）
> 状态：用户于本轮回复“确认”，本书面规格已获确认。尚未实施打包或创建 Release；Pi 依赖处理策略仍须独立审阅。
> 基线：本地优先 `main`；沿用已批准的对话优先与 BYOK 设计，不迁回旧在线平台。

## 1. 目标和范围

为当前 Electron 桌面工具建立可重复、可核查的三平台安装包流程。先修复现有外发和存储安全阻断项，再生成验证产物；验收后才公开 Alpha 预发布。源码在 GitHub 主线不意味着应用已经发布。旧平台分支继续只作备份，不部署 Vercel、GitHub Pages 或任何案件托管服务。

Alpha 功能清单只能列举实际通过行为测试的能力：本地普通/案件对话、材料导入与选择、受控发送确认、用户自配模型接口。PDF、连续上下文等既有设计能力须实现并验收后才能写入已支持清单。结构化证据链、材料导出、知识库检索和举报流程引导不在本次包装工程中追加，不宣称已经交付。

所有测试仅使用合成材料。Alpha 下载页和首次使用说明明确：实验性、不适合真实敏感案件、模型输出待核对，不构成法律意见或举报已提交证明。

## 2. 路径选择

推荐 **electron-builder + 平台原生 GitHub Actions**：与现有 Electron 入口匹配，可生成各平台常用格式，并把构建、产物验收与发布分开。

备选 Electron Forge：适合重新组织桌面构建工程，但本项目已有简单入口，没有必要同时迁移构建结构。仅本机打包也可先验证 Windows，但无法提供可复现的 macOS/Linux 证据，不作为最终流程。

本规格选择第一条路径。实施时固定并提交经过审阅的 builder 版本和 lockfile，不使用浮动 latest。继续固定现有 Electron；Pi 的安全升级/修补须独立审阅与回归，不借打包顺带升级。

## 3. 目标产物

| 平台目标 | 架构 | 格式 | 原生构建/验收要求 |
| --- | --- | --- | --- |
| Windows | x64 | NSIS `.exe` | Windows runner 构建；Windows 10/11 的实际验收系统版本逐项记录 |
| macOS | x64 | DMG `.dmg` | Intel macOS runner 构建；实际 macOS 版本单独记录 |
| macOS | arm64 | DMG `.dmg` | Apple Silicon macOS runner 构建；不以 Intel 启动结果替代 |
| Linux | x64 | AppImage `.AppImage` | Ubuntu x64 runner 构建；记录实际发行版、桌面环境、凭据后端及 AppImage 启动要求 |

这是四个目标、三种操作系统，不包含 Windows ARM、Linux ARM 或 macOS universal。目标列表不是支持声明；每个公开资产必须有对应的实际验收记录。使用 runner 时固定架构与明确版本，不把 `macos-latest` 当作架构证据。

构建与测试使用 Node 24 系列的固定版本；当前测试运行于 Node 25，尚不能证明 Node 24 兼容。打包后使用 Electron 内嵌运行时启动，也要独立验收，不能由系统 Node 测试代替。

## 4. 内容边界

应用入口保持 `app/desktop/main.cjs`，使用 ASAR。应用自有资源白名单为：

- `package.json` 的运行元数据。
- `app/desktop/main.cjs`、`preload.cjs`、`renderer.js`、`index.html`。
- `app/core/` 与 `app/agent/` 的实际运行模块，排除 `*.test.mjs`；不包含 `smoke-test.mjs`。
- 锁定的生产依赖与它们实际需要的运行资源、许可证；由构建器收集，不把整个开发 node_modules 当作资源复制。
- 项目许可证与必要第三方声明。

禁止包含案件、originals、对话记录、provider 配置/秘密、auth.json、环境文件、工作树、Git 元数据、浏览器数据、`.pi`、`.superpowers`、开发缓存、测试 fixture、旧平台、prototype 或研究文档全集。知识库目前没有运行期检索，不打包成暗中注入的上下文。

检查 ASAR 内外及 unpacked 目录的实际文件清单，不只检查 builder 配置。生产依赖的分发资源须逐项审核；SDK 的 CLI/示例/项目发现资源不能因默认收集就绕过审阅，也不能未经验证随意删掉运行必需文件。 native/WASM 等资源只有存在实际运行需要且验收通过时保留。

构建只在干净 checkout 中使用已提交 lockfile；不从本机数据目录取资源，不写入真实 Key。内容检查有意外文件即失败，不自动上传安装包。

## 5. 数据、原件与模型边界

本机 userData 保存案件和对话；应用更新不迁到服务器，不覆盖原始材料。卸载默认保留用户数据，卸载页与文档明确路径和保留行为；本轮不添加自动清空数据功能。用户自行清理或备份，发布流程不接触用户资料。

不内置 Key、不提供 Manbo API 中转。用户的 API Key 只经主进程凭据边界使用，不进入渲染器回传、案件记录、日志、测试截图或安装包。Linux 缺少可靠凭据后端或使用 `basic_text` 时必须拒绝保存 Key，不用静默明文回退。凭据加密不等于案件/对话已加密；不得宣传全盘加密或绝对安全。

导入/选择文件不联网。用户发送时确认接收方、本次实际附件表示、上下文和任务范围；请求变化则确认失效。云供应商可能按自己的条款留存已发送内容，取消不能撤回已经到达对方的数据。应用必须准确解释此边界，不使用“所有信息都在本机执行”或“工具无信息保护责任”作为免责承诺。

Pi 文件、终端、扩展、资源发现及自治工具保持关闭。安装包不能启用 Pi CLI、自动抓网页、自动举报或扩大文件访问权限。签名缺失也不是关闭 Electron 隔离、网络控制或原件保护的理由。

## 6. 构建与发布流程

1. 人工触发 build 工作流，选择已提交的 `main` 基线。默认权限仅 `contents: read`；固定第三方 Actions 引用，不向 fork/PR 任务注入签名或 API 秘密。
2. 在每个原生目标干净安装依赖，执行 Node 24 回归、审计和源文件边界检查。任何未处置生产 high/critical、测试失败或安全阻断未结案，禁止生成对外可下载资产。
3. 按四个目标打包，检查实际资源清单、Electron 启动与运行期依赖。检测意外文件/秘密失败则不上传。
4. 成功资产与清单通过 Actions artifacts 暂存 14 天。公共仓库的 artifacts 不能当私密储存，只允许合成验收资料，不上传真实用户数据。
5. 各目标进行安装/挂载或 AppImage 启动、重启恢复和卸载/移除验收；记录原件哈希不变和凭据行为。保存源码 commit、环境版本、产物 SHA-256 与验收结果，失败不转成平台支持声明。
6. 审阅者核对四个资产、门禁、许可证和发布说明；独立人工发布步骤才能创建版本 tag 与 GitHub **pre-release**。构建工作流不自动发布、不把 Alpha 标成 stable/latest，不引入自动更新器。

未来发布命名使用 `v0.1.0-alpha.1` 起的语义化预发布序列，只有验收与人工核对通过才创建实际 tag。四个目标作为同一候选版本一起验收；任一目标未通过时保留为候选，不悄悄把“三平台发布”改成单平台完成。回滚通过下架问题资产/标记撤回和选择上一已验收版本；不 force push 主线、不删除用户数据。

## 7. 真实性、签名与校验

每个最终资产提供 `SHA256SUMS.txt`，对应下载字节，不只校验 ASAR。SHA-256 用于核对下载完整性，不能替代签名或证明软件安全。清单与 release notes 同时记录源码 SHA、Electron/Pi 版本及测试系统。

当前没有签名证书或 macOS 公证资料。Alpha 可按未签名候选准备，但下载页必须明确 Windows 可能出现 SmartScreen、macOS 未签名/未公证且可能被 Gatekeeper 阻挡，Linux 资产未做发布者签名。不能声称已签名，不要求关闭系统防护、全局解除隔离或绕过平台政策。若系统阻止启动，该目标不能记为正常安装通过；先解决平台交付条件。

日后签名/公证为独立安全变更，证书只通过受控 CI Secret 注入，不进源码或产物；无需为本次源代码推送设置证书。

## 8. 错误与验收门禁

构建失败保留脱敏诊断，不回退到替身成功、不发布半成品；模型/解析失败保留用户草稿，不自动重复外发。安装失败不自动清空 userData。重复构建也不自动创建重复 tag/Release。

公开 Alpha 前必须逐项有行为证据：

- 普通问题无需案件；无附件请求不读取案件证据。
- 主进程实算材料哈希/大小，严格编码与路径/链接检查；预览与最终发送相同且不可变。
- PDF 实际解析、图片能力与限额、历史敏感段授权；没有实现的格式必须明确拒绝。
- UI 取消时序、重复确认、IPC sender 校验、provider 名称纯文本显示、并发本地记录与迁移。
- 真实 Pi 受控 HTTP/SSE 路径，DNS/IPv6、重定向、总体超时/大小和凭据不泄漏。受控 event-stream 测试不能替代这些检查。
- 干净安装后无未处置生产 high/critical；实际内容白名单与秘密检查通过。
- 四个目标分别安装/启动/重启/卸载、正确凭据后端、隔离与原件不变性验证。

当前上述总门禁未通过，尤其 Pi shrinkwrap 固定的 brace-expansion 5.0.9 漏洞仍未解决。不得为了推进 Alpha 给它添加 audit 忽略项或以关闭工具作为豁免。先审阅安全升级/可复现修补，再回归；本规格不授权直接更换 SDK 或手工补本机 node_modules。

## 9. 本规格审阅后的交付顺序

先制定剩余安全阻断项的修复计划，独立审阅 Pi 依赖处理策略；完成后再制定包装实施计划（builder 配置、内容检查、四目标 Actions、校验与发布文档）。不把包装工程当作补齐全部产品目标的机会。

书面规格和已经验证的源码修复已普通推送 `main`（`e06e782`）。用户已审阅确认本规格；下一步按上述顺序处理独立依赖策略和安全修复计划，不直接跳过前置门禁开始打包。当前没有安装包、tag、Release 或三平台验收完成声明。
