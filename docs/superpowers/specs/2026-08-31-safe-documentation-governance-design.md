# 慢波 Manbo 安全优先文档与治理设计

> 适用范围：本设计只覆盖研究报告、README、知识库和发布治理文档；不包含应用代码、部署配置或真实用户数据。

## 目标

把仓库从“概念方案已验证”的叙述，收敛为可审计、可持续更新、以举报人安全为先的项目基线。文档必须区分已核实事实、设计假设和待核实事项；产品路线必须以发布门槛约束高风险功能。

## 主要问题

1. README 把尚未开发的能力写成平台能力，并声称研究与知识库“已完成并核实”。
2. 研究报告含来源占位符、二手或不可复核来源，以及若干已发现的事实错误或过度确定表述。
3. “全球公开举报、证据托管、跨用户聚类、地图和 B2B API”同时进入早期路线，未设置数据保护、诽谤、滥用和安全事件门槛。
4. 知识库缺少证据状态、变更记录、发布阻断规则和数据保留最小化要求。

## 设计决策

### 1. 证据分级

所有重要主张标记为：

- **已核实**：可追溯到官方法律文本、官方机构页面或项目内已审阅的一手材料。
- **设计假设**：产品或技术建议，不代表现有能力或法律事实。
- **待核实**：来源不足、处于修法期、日期属于未来，或需要目标法域律师确认。

报告不得把待核实内容写成事实；知识库中待核实内容必须带时效提示和官方链接。

### 2. 产品分阶段门槛

- **MVP**：仅提供法域确认、ILO 指标自述、证据安全清单、官方渠道链接和本地/短期会话导出；不托管原始证据、不公开公司页面、不做跨用户关联。
- **V1 门槛**：在 DPIA、威胁建模、删除/保留测试、人工审核 SOP、申诉流程和目标法域法律审查完成后，才评估加密证据托管。
- **V2 门槛**：在内容审核、通知-行动、公司回应、申诉、透明度报告和跨境传输机制完成后，才评估公开聚合页面或地图。
- **V3 门槛**：只有在数据质量、来源许可、API 安全和商业/公益治理获批准后，才评估 B2B API 或趋势产品。

### 3. 风险治理

新增风险登记册与发布前门禁，至少覆盖：人身报复、隐私/数据保护、诽谤与 SLAPP、恶意内容、AI 误导、第三方供应商、账号与密钥、跨境传输、可及性和运维恢复。每项风险包含触发器、责任人、控制措施、证据和发布阻断条件。

### 4. Git 静默认证

项目使用 Windows Git Credential Manager 保存凭据，并设置 `credential.interactive=false`。凭据有效时 Git 操作不弹窗；凭据失效时命令直接失败。远程 URL 不包含 token 明文。

## 交付物

1. `docs/research-and-plan.md`：重写为带证据状态、范围、决策门槛和修订路线的咨询报告。
2. `docs/risk-register.md`：风险登记册、指标、责任与发布阻断规则。
3. `docs/release-gates.md`：MVP/V1/V2/V3 发布门禁清单。
4. `knowledge-base/README.md`、`knowledge-base/AGENT-GUIDE.md`：加入证据状态、来源分级、冲突处理、数据最小化和发布门禁。
5. 所有知识库 frontmatter 的 `last_verified` 更新为本次审阅日期；纠正中国批准 ILO C29/C105 的错误陈述。
6. `README.md`：准确描述当前状态、明确非产品承诺，并链接治理文档。

## 验证标准

- `rg` 不再发现来源占位符。
- README、研究报告和知识库对“当前能力/未来建议”无相互矛盾表述。
- 研究报告明确列出数据缺口、法律审查边界和未来日期的待核实状态。
- 所有知识库 Markdown 文件含 frontmatter，且不再包含关于中国批准状态的错误文本。
- Git 远程 URL 不含 `ghp_` 或 `password=`；`credential.interactive=false` 已生效。
