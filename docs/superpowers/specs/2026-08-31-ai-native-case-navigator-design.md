# AI-Native 强迫劳动举报档案与渠道导航设计

> 版本：v0.1（2026-08-31）  
> 适用范围：首个可开发版本及后续外部渠道适配；不包含立即公开公司页面、原始证据托管或自动代用户提交。

## 1. 目标与核心决策

### 1.1 目标

把自然语言对话作为举报准备的主要入口。用户不需要先填写复杂表格，AI 通过多轮、可暂停的对话提取事实，生成可编辑的结构化举报档案，并帮助用户理解 ILO 指标、材料覆盖情况和可能相关的法域法律与官方渠道。

### 1.2 核心决策：不打分、不认定

系统禁止以下输出和产品机制：

- 数字化证据分数、概率、风险百分比、排名或“通过/不通过”；
- “已经违反某法律”“构成强迫劳动”“举报成功率”等法律或结果性结论；
- 根据报告数量对公司、地区或用户排序；
- 将证据“完整”误写成法律上的“充分证明”。

系统允许的定性状态仅用于说明信息覆盖程度：

| 对象 | 允许状态 | 含义 |
|------|----------|------|
| ILO 指标 | 命中 / 未命中 / 信息不足 | 用户叙述或文件要素与指标的对应关系 |
| 证据覆盖 | 已覆盖 / 部分覆盖 / 缺口明确 | 是否包含官方渠道通常需要的事实字段或材料类型；不判断违法成立 |
| 法律导航 | 可能相关 / 适用前提不明 / 当前未覆盖 | 基于确认法域和来源的导航提示 |
| 危机状态 | 需要立即安全转介 / 可继续整理 / 未发现触发信号 | 内部流程控制，不向用户输出严重度等级 |

## 2. 产品范围

### 2.1 MVP 功能列表

| ID | 功能 | 用户价值 | 主要验收标准 |
|----|------|----------|--------------|
| F-01 | AI 对话入口 | 用自然语言、多语言和分段叙述开始 | 首屏说明能力边界；支持暂停、跳过和结束；不要求先填写表格 |
| F-02 | 危机筛查 | 在暴力、拘禁、自伤、未成年人或贩运信号出现时先保护安全 | 危机信号优先于其他提问；停止证据追问；显示所在地相关资源或请求确认所在地 |
| F-03 | 法域确认 | 避免把行为地、用户所在地和产品流向混为一谈 | 分别询问三类地点；用户可选择“不愿回答”；未确认时不映射具体法条 |
| F-04 | 事实抽取 | 从对话提取角色、时间线、工作关系、地点、产品与雇主信息 | 每个抽取字段显示原文依据；用户可编辑、删除或标记“不确定” |
| F-05 | ILO 指标矩阵 | 让用户看到哪些描述与 11 项指标相符 | 逐项显示命中/未命中/信息不足及依据摘录；不得只显示命中项 |
| F-06 | 三要件检查 | 识别工作/服务、非自愿、惩罚威胁是否有事实支持 | 输出覆盖情况与待澄清问题；不生成法律结论或数字分数 |
| F-07 | 证据覆盖清单 | 告知材料是否覆盖常见官方提交字段 | 显示已提供、缺口和安全替代方式；明确“没有材料也可以保存/咨询”；不建议冒险取证 |
| F-08 | 法律导航 | 根据确认法域和产品流向提供可能相关的法律入口 | 仅检索带来源、状态和核实日期的知识库；`needs-review` 必须显式提示 |
| F-09 | 渠道比较 | 帮用户比较 2-3 个官方/NGO 选项 | 显示匿名性、是否反馈、适用范围和用户需自行完成的步骤；不承诺结果 |
| F-10 | 结构化档案预览 | 让用户在保存前检查 AI 是否理解正确 | 档案包含事实、时间线、指标、证据覆盖、法律导航、危机标记和同意记录；所有字段可回溯到原文 |
| F-11 | 私密档案存储 | 平台作为用户档案载体 | 默认仅本人可见；支持草稿/已确认/已导出/已删除状态；不保存原始证据文件 |
| F-12 | 用户控制的导出 | 便于用户自行保存或提交给第三方 | 导出 Markdown/JSON/PDF 至少一种格式；导出前显示字段清单和免责声明；不显示“已提交” |

## 3. AI-Native 交互设计

### 3.1 对话状态机

```text
WELCOME
  -> SAFETY_CHECK
  -> JURISDICTION_CONTEXT
  -> FACT_GATHERING
  -> ILO_MAPPING
  -> EVIDENCE_COVERAGE
  -> LEGAL_NAVIGATION
  -> CHANNEL_OPTIONS
  -> USER_REVIEW
  -> SAVE_OR_EXPORT
```

任意状态检测到危机信号都转入 `SAFETY_ESCALATION`；用户可以回退、跳过或结束。单轮最多 3 个问题。AI 必须在每个阶段显示“我目前理解的内容”，由用户纠正后才写入档案。

### 3.2 AI 输出契约

```json
{
  "facts": [{"field": "...", "value": "...", "source_quote": "...", "certainty": "user_stated|uncertain"}],
  "timeline": [],
  "ilo_indicators": [{"id": 1, "status": "hit|not_hit|insufficient", "basis": [], "missing": []}],
  "elements": {
    "work_or_service": {"status": "covered|partial|unknown", "basis": []},
    "involuntary": {"status": "covered|partial|unknown", "basis": []},
    "penalty_or_threat": {"status": "covered|partial|unknown", "basis": []}
  },
  "evidence_coverage": [{"topic": "...", "status": "covered|partial|gap", "safe_options": []}],
  "legal_navigation": [{"jurisdiction": "...", "source_id": "...", "status": "possible|needs_review|not_covered", "premise": "..."}],
  "referrals": [],
  "safety_flags": [],
  "disclaimer_ids": ["ai-assessment", "legal-reference", "user-decision"]
}
```

JSON Schema、枚举值和来源 ID 由版本控制；无法满足 schema 时，系统降级为静态知识库回复，不展示部分生成结果。

### 3.3 证据覆盖而非证据评分

“证据覆盖”只回答：“提交材料是否包含某类渠道通常需要的要素？”例如公司/厂区标识、时间线、工作条件、工资记录、威胁描述、产品流向。系统必须同时显示：

1. 用户已提供的事实或材料类型；
2. 尚未覆盖的字段；
3. 不需要冒险即可补充的选项；
4. 无法判断或来源不明的内容。

不允许把“已覆盖”转译为“足以证明违法”，也不允许用百分比、星级、颜色等级或排序强化这种误读。

## 4. 规范化案件模型与数据边界

### 4.1 Canonical Case Record

```text
CaseRecord
  case_id（随机、不可从用户身份推导）
  account_id（伪名账户）
  consent_version / visibility / lifecycle_status
  jurisdiction_context（行为地、用户地、产品流向地，可为空）
  facts[] / timeline[]
  ilo_indicators[] / elements{}
  evidence_coverage[]（不含原始文件）
  legal_navigation[] / referrals[]
  safety_flags[]
  source_trace[]（对话消息 ID、知识库 source_id）
  created_at / updated_at / deleted_at
```

### 4.2 数据最小化规则

- MVP 不保存原始图片、文件、护照号、证件照片、完整 IP、设备指纹或不必要的联系方式。
- 叙述中的个人姓名、电话、精确地址默认脱敏或提示用户删除；保留前必须由用户确认。
- AI 供应商只接收完成必要脱敏的文本；合同需明确不用于训练、留存期限和分包商。
- 删除应作用于主库、搜索索引、缓存和备份队列；不能实现的范围必须在保存前明示。
- 任何向外部机构共享都使用独立同意，不继承“保存档案”同意。

## 5. 外部系统接入设计

### 5.1 适配器接口

```text
Connector.describe() -> 目标机构、法域、支持字段、附件规则、当前核验日期
Connector.validate(case_record) -> 字段缺口与不可发送字段
Connector.preview(case_record) -> 用户可读的发送预览
Connector.submit(case_record, user_confirmation) -> reference_id | manual_handoff
Connector.status(reference_id) -> unknown | received | processing | closed
```

任何 `submit` 必须接收用户明确确认；无 API 时返回 `manual_handoff`，生成官方网页入口和导出包。平台不伪造“已受理”，只有目标机构返回参考编号或可验证回执时才记录 `received`。

### 5.2 首批适配顺序

1. **导出适配器**：通用 Markdown/JSON/PDF，验证规范化案件模型。
2. **CBP/美国进口线索**：依据 CBP 当前官方字段清单做预览和导出，不自动发送。
3. **BAFA/德国供应链投诉**：完成法域和用户授权模型后再评估。
4. **其他劳动监察、NGO 和欧盟渠道**：逐个建立来源、字段和责任边界，不做“全球统一接口”的假设。

## 6. 安全、法律与质量控制

### 6.1 必须通过的控制

- 所有输出带固定免责声明；涉及公司名称时附“用户报告，未经独立核实”。
- 法域未确认时不引用具体条文；法律文件超过 90 天未复核时显示时效提示。
- 任何暴力、拘禁、自伤、未成年人或贩运信号优先安全转介。
- 模型不可用、来源不可用或 schema 校验失败时，降级到静态信息，不生成幻觉内容。
- 对话、档案和导出均提供用户纠错、删除和撤回入口。

### 6.2 质量指标（只用于内部测试，不向用户打分）

- 危机信号召回率；
- 法律结论越界率；
- ILO 指标引用正确率；
- 原文依据可追溯率；
- 法域误路由率；
- 用户纠错成功率和删除成功率；
- 外部 connector 字段校验错误率。

## 7. 阶段路线图与 WBS

### WBS 0：产品与合规基线

**目标**：锁定 AI-Native 边界、来源状态和风险责任。  
**交付物**：本设计、风险登记册、发布门禁、知识库状态。  
**验收标准**：无数字评分机制；所有后置功能有进入条件；责任角色和回滚路径明确。

### WBS 1：知识库与检索层

**目标**：提供可追溯、可过期降级的 ILO/法律/渠道检索。  
**交付物**：版本化 source registry、检索过滤器、90 天复核任务。  
**验收标准**：每条法律导航结果带 source_id、法域、核实日期和 evidence_status；`needs-review` 不触发确定性法条输出。

### WBS 2：AI 对话与危机状态机

**目标**：以对话完成安全筛查、法域确认和事实收集。  
**交付物**：状态机、提问策略、危机转介模板、JSON Schema。  
**验收标准**：黄金案例覆盖普通、信息不足、多语言和危机场景；危机状态不会继续询问证据；单轮不超过 3 问。

### WBS 3：结构化档案与用户控制

**目标**：把 AI 理解变成用户可修改、私密保存的 CaseRecord。  
**交付物**：档案 API、预览/纠错/删除、生命周期状态、导出器。  
**验收标准**：每个字段可追溯到原文；默认私密；删除覆盖主库和异步清理队列；导出不声称已提交。

### WBS 4：证据覆盖与法律导航

**目标**：说明材料覆盖和法律相关性前提，不作评分或认定。  
**交付物**：指标矩阵、三要件检查、证据覆盖清单、渠道比较。  
**验收标准**：输出命中/未命中/信息不足；覆盖状态不出现数字、星级或颜色等级；未确认法域不出具体条文。

### WBS 5：外部系统适配器

**目标**：让用户在确认后把规范化档案转换为官方/NGO 所需格式。  
**交付物**：Connector 接口、通用导出适配器、首个目标机构适配器。  
**验收标准**：提交前有字段预览和独立同意；API 不可用时可人工跳转；无回执不显示 received。

### WBS 6：安全、可及性与发布

**目标**：证明系统不会以错误安全承诺或 AI 越界方式上线。  
**交付物**：威胁模型、DPIA（适用时）、红队报告、WCAG 检查、运行手册。  
**验收标准**：Gate 0/1 全部通过；高危错误可回滚；静态危机资源在模型/网络故障时仍可访问。

## 8. 非目标

本设计不授权以下行为：替用户作法律认定；代表用户向雇主或政府施压；自动向外部机构发送未经确认的举报；以举报数量制作企业排名；保存或公开原始证据；用 AI 生成用户未陈述的事实；把平台描述为政府、NGO、律师或执法机构。

## 9. 设计验收清单

- [ ] 产品文案明确“AI 是信息整理助手，不是法律认定机关”。
- [ ] 任何界面、API 或提示词均不存在 score、probability、rank、success-rate 等字段或同义机制。
- [ ] CaseRecord、知识库来源和 connector 均有版本号与审计记录。
- [ ] 用户可在保存前查看、修改、删除和选择不共享字段。
- [ ] 公开展示、原始证据托管和自动提交不会因 MVP 配置错误而启用。
