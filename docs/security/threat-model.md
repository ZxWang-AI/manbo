# Manbo 威胁模型

> 版本：v0.1（2026-09-02）  
> 方法：按资产、信任边界、攻击者、滥用场景和剩余风险审阅；上线前需由独立安全审阅人确认。

## 1. 资产

| 资产 | 敏感性 | 保护目标 |
|------|--------|----------|
| 用户自述、对话消息、修订稿 | 可能含特殊类别个人数据 | 私密、完整、可删除、不可被模型越权外发 |
| 原始图片、文件、录音和转写 | 极高，可能暴露身份和地点 | 加密、隔离扫描、不可变版本、最小权限 |
| 案件版本、AI 初审和管理员标注 | 高 | 版本可追溯，工作流状态不被解释为事实或法律结论 |
| 恢复密钥与包裹密钥 | 极高 | 只保存恢复密钥哈希；密钥可轮换、吊销和清理 |
| 法律/渠道知识库 | 中 | 来源 ID、法域、核实日期和过期状态可追溯 |

## 2. 信任边界

```text
浏览器/用户设备
  -> Next.js API（输入校验、RBAC、PII 提示、速率限制）
  -> PostgreSQL（案件/消息/版本）
  -> 加密对象存储与扫描隔离区
  -> 供应商中立 AI Gateway（仅接收确认后的脱敏文本）
  -> 外部官方/NGO 链接（只导航，不代提交）
```

浏览器是不可信边界；客户端 MIME、文件名、content ref、cookie 和表单字段都必须由服务端重新校验。模型输出是不可信边界；所有输出经过 schema、来源 ID、法律结论和禁止字段检查。

## 3. 攻击者与滥用场景

| 攻击者/场景 | 可能结果 | 当前缓解 | 剩余风险 |
|-------------|----------|----------|----------|
| 恶意用户上传脚本/压缩炸弹 | 执行、资源耗尽、解析污染 | 签名/MIME 双检、隔离、资源上限、危险格式不执行 | 真实沙箱和扫描集群尚未演练 |
| 提示注入或伪造来源 | AI 越权、编造法条或误导用户 | 本地危机预检、严格输出契约、知识 ID 白名单、静态降级 | 模型/网关组合仍需红队和人工抽检 |
| 账号接管或越权管理员 | 读取或修改案件 | 恢复密钥哈希、RBAC、独立管理员版本、乐观并发 | 生产 OIDC/SSO、MFA 和异常登录告警尚未接入 |
| 供应商日志/备份泄露 | 特殊类别数据外泄 | PII 提示、最小化、加密设计、供应商留存审查要求 | 零留存合同、KMS、备份清理尚未证明 |
| 公开聚合或恶意重复举报 | 诽谤、反向识别、错误关联 | MVP 不公开、不聚类、不排名、不提供黑名单 | 未来公开能力需单独治理和法律审查 |
| 管理员低频审核遗漏危机案件 | 用户误以为有人及时跟进 | 明确不承诺人工响应；危机流程前置 | 需定义值班/升级 SLA；当前无访问异常告警 |

## 4. 关键控制要求

1. 原始材料必须先加密、扫描、授权后才可读取；`saved_unread`、`quarantined`、`blocked_malicious` 永不进入 AI 内容引用。
2. 管理员查看、播放和下载不写应用级访问历史，但授权必须始终由 RBAC 强制；管理员标注、修改和删除只能追加不可变版本。
3. AI 不得输出评分、概率、排名、真实性断言、法律认定或“已提交”状态；失败时不写案件更新。
4. 删除必须阻断读取并排队清理对象、派生物、包裹密钥、缓存和备份；清理任务幂等且可重试。
5. 审计事件采用白名单 metadata，不含原文、完整请求标识、IP、设备标识或凭据。

## 5. 剩余风险与发布决定

在真实对象存储/KMS/扫描/备份、生产身份系统和独立安全测试完成前，方案 A 只能用于本地或受控 staging。平台不承诺绝对匿名或绝对安全；在线行为仍可能留下网络、设备和证据反推痕迹。
